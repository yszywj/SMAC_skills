# 人族与虫族技能

## 2026-10-30 人族订单生命周期与分阶段移动（v7）

在v6上将保持订单改为能量/接近进展驱动，增加停滞退出和未确认跟随的有限预算；已有原生治疗的持续条件与新Heal候选距离分开。医疗机预测区分起步、加速、巡航与转向，同阶段传播误差；接近意图加入到达时间和近期掉血检查。原动作接口、地面集火和撤退阈值保留。

沿用种子170–209完成40局，16胜24负，与v6胜局集合一致；消灭比例69.00%→69.75%，存活比例25.25%→25.50%。结果与机制证据见`sc2_skill_adapter/analysis/terran_lifecycle_v7_20261030/REPORT.md`。保持动作使用次数不是治疗量；预测误差改善也不能单独归因于胜负。

v6兼容回放需同时关闭`heal_escort.V7_PARAMS['enabled']`和`terran_motion.V7_ENABLED`。正式v7保持两者开启，并沿用`--terran-keep-heal-order`。本轮没有修改虫族或通用战斗控制器。


## 2026-10-30 人族协同修订（v6）

本轮在v5基础上修正人族风险评估，合并治疗与撤退协调，并为医疗机增加显式可选的订单保持能力。治疗评分、危急切换阈值和实际订单占用/释放规则继续沿用v4。虫族与默认off策略不启用这些人族组件；关闭v6总开关用于复现v5动作，不能把组件历史观察回放当作新胜率。

- 风险评估区分已确认无兼容武器与武器资料未知。已确认不攻击的医疗机不再产生虚构的威胁/齐射压力；API空武器列表本身不足以证明无攻击能力。该修正在人族v6显式启用。
- 一个协调器从原战斗动作、旧支援撤退候选及治疗配对中选择最终动作。只改已处于撤退状态的地面单位；攻击、恢复和重新站位同样被监测，但其地面动作不因治疗协调而覆盖。每单位每局最多两次最终支援改向，不重置原战斗撤退预算。
- 空闲且没有实际治疗订单的可用医疗机，可对短期内安全可达、未被占用的伤员生成接近意图。接近仅提交移动，不能计作治疗分配；意图有时限、真实缩距要求和退出条件。后续观察提供合法治疗候选后才转入治疗。
- 运动预测使用双方的实际位移、动作/订单切换及附近地面单位信息，给出局部位置估计和工程误差余量。误差余量不是统计置信区间；碰撞、路径和医疗机自动跟随仍不被当作已知结果。
- 真实武器暴露和可见基础齐射压力仍不得增加。生命值不超过25%、确有治疗候选或实际治疗订单的伤员，在明确主目标存在时可允许最多一个控制窗口的额外预计重入延迟；连续观察确认移动受阻、缺少进展时，支持每单位每局最多一次受限反向，不能用普通转向请求绕过约束。
- `--terran-keep-heal-order`在适配器原动作编号末尾追加独立动作（本轮10v10为16）。它只适用于已观察到的有效医疗机治疗订单，表示本窗口不发送该单位的新原生命令；不等于Stop、不新发超距治疗，也不证明实际回血。策略在没有该目标合法治疗候选时至多保留一个窗口，随后按观察到的订单、进展、能量和危险重新决策。
- 动作扩展默认关闭，仅允许`adaptive-skill/current/terran/native`显式开启。运行元数据单列`action_extensions`，保持原清单和环境参数；因此与v4/v5比较时必须披露动作接口变化。死亡单位0动作和1号Stop的原有含义不变。

本轮实现、受控订单实验、离线组件检查与40局方案/结果位于`sc2_skill_adapter/analysis/terran_coordination_v6_20261030/`。正式对比沿用种子170–209的原40局manifest，与v4、v5各16/40胜逐局比较；受控实验不计入这40局。运行前冻结源码、依赖、检查记录和参数，中途不调策略或挑选对局。

## 2026-10-30 人族治疗协同（v5，第一阶段）

本轮以人族v4为基线，新增内部HealEscort治疗与撤退协同。治疗匹配评分、危急切换阈值、医疗机闲置跟随、集火和原有撤退预算保持v4规则。虫族仍为v4，默认off行为不变。

- 只处理已决定撤退的地面伤员，读取当前真实治疗订单和本步合法治疗分配；后者仍为待确认请求，不能提前计作治疗成功或释放旧目标。
- 在v4原定撤退预计脱离公开治疗候选距离、且存在同等或更安全且不拖延已知重入机会的合法方向时，才考虑替代方向。保留反向保护及每单位每局两次支援重定向上限，不扩大撤退次数或时长。
- 医疗机本步最终动作必须仍是对该伤员的合法治疗。第一阶段不新增主动医疗机覆盖布局，不把普通移动与治疗当作同一动作，不修改正常攻击或等待冷却的动作。
- 使用一个控制窗口的局部移动估计；医疗机自动跟随、碰撞、未来寻路和实际治疗量不被假定为已知。缺少有效公开数据时保留原策略。订单确认和断开原因用于诊断，不把净生命变化当作恢复生命值。
- 后续调整治疗排序与抢救阈值属于独立阶段，不包含在本轮。实现细节与有效参数以冻结源码及测试记录为准。

本轮40局人族10v10方案与结果：`sc2_skill_adapter/analysis/terran_heal_escort_v5_20261030/`。沿用原场景及种子170–209，与v4的16/40胜逐局对比；不将历史观察回放当作新策略胜率。以下各节保留版本演变。

## 2026-10-28 拆分验证版（v4）

v3组合改动未带来整体胜率提升，本轮恢复v2的相关策略，单独检验保留组件，运行前冻结后各族40局。

- 人族为**v2支援位置/接近/有限撤退 + v3受控危急治疗切换**。关闭v3主动覆盖分区及位置预测，恢复原有最大友军群跟随与安全接近伤员；实际订单占有、释放确认、危急切换请求/确认和冷却保留。旧coverage记忆不参与决策。
- 虫族为**v2避让/拦截 + v3团队目标继承**。恢复v2的固定几何阈值、非贴身两步预算和反向限制，移除v3动态风险预测及速度记忆；跳虫继承团队集火与底层撤退/恢复，只在可验证受阻时局部重试。我方毒爆聚群算法不改。
- 恢复v2避让是为了隔离组件效果，并不表示它的已知边界已经解决。v4结果需同时与v3和v2比较：前者检验去除组件的影响，后者检验保留组件的净影响。
- 默认off、共享底层和全部评测参数不变。v2/v3源码与结果均保存在历史实验冻结目录。

方案和结果：`sc2_skill_adapter/analysis/race_skills_v4_20261028/`（相对SMAC_agent根目录）。本节记录v4组合，当前人族以顶部v6说明为准。

## 2026-10-28 协同修复版（v3）

本轮保留独立种族控制器和默认off行为，在v2基础上调整以下决策；具体阈值、边界与遥测以源码为准。

- 人族：保留实际治疗订单和目标占有权。当前目标稳定、另一合法且未被占用的伤员明显更危急时，允许受控切换；记录请求和观察确认，使用冷却抑制反复换目标。两机目标交接仍须等待观察确认释放。
- 人族：空闲运输机按地面承伤/输出小组和已有治疗覆盖分配支援位置，以最终地面动作估计下一窗口位置，安全候选中优先补足覆盖。已有有效治疗不因位置优化被取消；支援撤退仍要求合法治疗分配，不追逐远处医疗机。
- 虫族：跳虫优先保留底层团队集火、撤退和恢复决策，局部重选仅处理缺少可用目标或持续受阻等情况，避免最近目标无条件覆盖全队分工。
- 虫族：反毒爆以连续可见位置和原生移动速度估计下一控制窗口接触风险。允许必要的反向撤离；取消两步到期强制返攻。保护开火和预计击杀拦截均须满足射程/时机条件，危险仍在时可继续避让。
- 上述预测均为局部几何启发式，未新增爆炸半径、隐藏信息、实际命中或未来伤害的断言。我方毒爆聚群目标算法、通用All-in和底层默认off策略本轮不改。

该轮真实40+40局方案和结果目录：`sc2_skill_adapter/analysis/race_skills_v3_20261028/`（相对SMAC_agent根目录）。历史v1/v2快照与结果保留；本节及以下文字用于说明演变，当前行为以上方版本说明为准。

## 2026-10-28 修复版（v2）

- 人族治疗以当前观察到的订单为依据。合法、未受危的持续治疗先保留；其他运输机不得争抢已被实际订单占用的目标。即使原治疗机本步取消/撤离，也须等下一帧确认订单释放后才能交接，避免同时交换目标被拒却误记为成功。计划、观察订单分开记录。能量低于1时不新发治疗命令（基于本项目实测反馈的保守门槛）。
- 无分配且有远处伤员时，运输机保留HealAssign的接近建议，并检查已知对空威胁；受危运输机保留自保建议。
- 人族支援撤退要求当前确有运输机合法分配给该伤员，不再仅凭远处有运输机就改方向。种族撤退覆盖统一检查：威胁数量和可见基础齐射压力不增加、预计重新开火不延后、避免反向/返回上一位置。仍保留每单位每局最多两次支援重定向。
- 刺蛇朝跳虫掩护的撤退重定向还要求比原撤退有明确的威胁数量或基础齐射压力改善；仅仅更靠近跳虫不够。
- 普通虫族单位面对较远毒爆时保留当前可行开火窗口；可合法发射、原生射程内且预计单次攻击足以击杀的毒爆优先拦截。非贴身紧急情况连续避让最多两步，之后交还普通战斗决策一窗口；贴身紧急情况允许继续避让。避让记录连续计数及例外原因，非紧急避让不得直接反向。
- 1.5距离、贴身几何阈值及两步预算均是启发式，不是爆炸半径或命中保证。共享底层默认off策略不变，毒爆聚群目标算法本轮不调整。

验证与真实40+40局结果见 `sc2_skill_adapter/analysis/race_skills_repaired_20261028/`（相对SMAC_agent根目录）。以下保留初版迁移来源与接口说明；行为差异以上述v2规则为准。

本版增加两个独立组合控制器，复用现有基础技能，不修改冻结历史版本。默认 `race_profile="off"` 仍执行原 AdaptiveFocusFire。人族与虫族策略需要显式启用，仅适用于当前三兵种场景。

## 已实现内容

| 控制器 | 迁移来源 | 初版行为 |
|---|---|---|
| `terran_combat.allocate_terran_combat` | AdaptiveFocusFire、HealAssign、移动评分与群体几何 | 输出单位沿用原集火/撤退；运输机接入联合治疗分配，跨窗口保持分配记忆；空能量/闲置运输机跟随友军主要群体；按确认可对空的武器判断威胁；明确不兼容目标被排除；已决定撤退的单位可有限地向治疗支援调整方向。 |
| `zerg_combat.allocate_zerg_combat` | AdaptiveFocusFire、集火预算、接敌与移动评分 | 跳虫分配局部目标并在连续受阻后侧移；刺蛇撤退偏向近战掩护；毒爆独立分配可见目标群并接近，排除普通伤害预算/低血撤退；逼近的敌毒爆可触发打断攻击的分散避让，协调候选落点。 |

人族支援撤退只修改原策略已经选择撤退的单位，且不得增加已知威胁覆盖，每单位每局最多调整两次方向。它不是额外获得两次撤退时间，也不会重置原撤退预算。

治疗仍采用现有一对一匹配。治疗动作会实际发给引擎，不把Stop当成“保持治疗订单”；`AlreadyTargeted`等原生反馈照实记录，不记作新增治疗量。未知武器兼容性不被断言为确认威胁。

毒爆的目标聚集距离、警戒距离是几何启发式，**不是已校准的爆炸半径/伤害**。没有用毒爆消失来推断命中；普通单位的最终攻击预算重新计算，不计毒爆未知爆发伤害。毒爆从原All-in兵力比例的分母和分子中排除，避免正常消耗直接触发该比例条件。

## 使用方式

Python接口（从 `SMAC_agent` 根目录导入）：

```python
from skills.current.skill_manager import SkillManager

manager = SkillManager(race_profile="terran")  # 或 "zerg"；默认 "off"
manager.select("adaptive_focus_fire", posture="balanced")
actions, telemetry = manager.step(payload, n_agents=10)
# 每局开头调用 manager.reset()，每步将最终动作交给现有运行器。
```

`race_profile` 只改变组合战斗模式；显式选用其他独立技能仍执行该技能原来的行为。两个新模块的纯函数接口与原分配器兼容，并增加 `race_memory` 输入和返回值。Manager负责跨窗口记忆、换局清理、同一观察重复调用缓存和被覆盖动作的旧接敌历史清理。

SMACv2 CLI（在 `SMAC_agent/sc2_skill_adapter` 执行）：

```powershell
.\.venv\Scripts\python.exe -B run.py scenarios --race terran --size 10 --episodes 10 --seed 3000 --unit-balance native --output configs/terran-initial-n10.json
.\.venv\Scripts\python.exe -B run.py run --method adaptive-skill --skill-version current --race-profile terran --manifest configs/terran-initial-n10.json --output-dir runs/terran-initial-n10
```

虫族将两处 `terran` 替换为 `zerg`，并使用独立输出目录。新参数不自动开启原有 `--adaptive-*` 优化或空间技能；如需与此前v7组合比较，应在两组中一致传入此前的优化开关和单位价值参数。测试输出目录必须未使用。

历史 `--skill-version baseline_*` 拒绝种族策略。CLI也拒绝与清单种族不匹配或配合非 `adaptive-skill` 方法使用。SMACv1 CLI暂未新增种族开关；通用Python Manager接口可用，但该环境的种族策略尚未做真实验证。

## 日志与验证

- `run.json` 的 `skill_parameters.race_profile` 记录显式种族配置，新源码纳入哈希。
- 每步 `race_telemetry` 记录治疗、动作替换、毒爆目标、几何参数和已清理的历史；普通攻击预测以最终动作重算。
- `skills/tools/verify_race_profiles.py` 用历史真实观察检查新动作合法性、输入不变、重复调用不重复消耗预算，并比较默认off与冻结v7动作是否相同。
- 该离线检查不能产生新胜率：后续观察由旧策略产生，并非新动作造成。

## 当前未完成的优化

本次是可运行的初版，尚未完成全部种族战术：人族对空火力预留、治疗净收益预测和完整射程阵型；虫族严格同步接敌、精确爆炸效果建模、反毒爆中原地击杀与逃离的权衡；两族集结/搜索的专门参数校准。现有Regroup/CohesiveSearch/CombatPositioning开关仍独立，未声称已针对两族调优。

只输出当前接口支持的移动、Stop、攻击/治疗动作；未添加兴奋剂、装载/卸载、潜地或手动自爆。没有新胜率保证，应先检查实际对局，再以独立种子做对照评测。

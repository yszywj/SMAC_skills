# EXPERIMENT_PROTOCOL（人族医疗机治疗偏好评分器）

## 对照定义

- **A**：冻结基线（见 BASELINE_AUDIT.md；run 级源码哈希已存）。
- **A-plug**：经新注入层但用原评分。验收：同观察序列下最终动作/订单/预算/记忆与 A 逐位一致。离线已证（RESULTS §1）；真游戏等价待 SC2。
- **T**：教师控制全部基础动作——仅诊断用；教师无 keep 扩展语义，协议单列，不与 A/B/C/D 同表比较。
- **B**：原 skill + 真实教师治疗评分（`pair_scoring="on"` + teacher-score）。
- **C**：同 B 结构，原生树评分。
- **D**：同 C，导出 if/else 规则评分；C/D 同观察动作/记忆/遥测一致性测试通过后才作为部署模型。

接入模式：`off / shadow / teacher-score / tree-score`（`integration/runtime.py:integration_kwargs`，默认 off 时零对象、零重依赖导入、零随机数、零网络）。

## 场景划分（不重叠；逐局比较初始化状态哈希，非仅种子）

1. 冒烟 5–10 局（不产生胜率结论）
2. 教师筛选 40 局
3. 教师资格验证 200 局（不用于梯度训练；候选比较 ≤3）
4. 树训练 ~400 局（A/B 轨迹各半，可按预算上限扩充）
5. 树验证 100 局（不与 2/3 重叠）
6. 最终测试 200 局（全部冻结后执行一次；公布后不回调重报）
7. 迁移集（5v5/未训练分布），第一阶段后单独评估

新场景编号自 210 起分配；与 runs 已用 170–209 按初始化哈希查重。无医疗机对局保留在总胜率分母中。

## 资格与统计准则（预注册）

- 接口全通过 = 最多"可运行候选教师"。
- 40 局筛选不据此声称增强。
- 教师资格：B−A 配对胜率差点估计为正且 95% bootstrap 配对区间下界 > −5pp → "暂可用于实验蒸馏"；下界 > 0 → 报告提升证据；跨 0 → 证据不足。
- T 的全队结果不代替 B 的混合控制结果。
- 统计按对局/场景成组：配对胜负表、bootstrap 区间、原始局数、无效局数；不把候选行当独立样本。

## 报告字段（强制）

总体/按医疗机数量(0/1/2+)分组胜率、有效与无效局数、配对胜负变化与区间、敌灭比例、己方存活、任务影响率（模型实际改变配对的比例）、覆盖/回退比例、订单确认与 AlreadyTargeted 拒绝数、决策耗时、教师调用量、原始逐局记录。严格评测遇教师失败/schema 不符/非有限分 → 该局 invalid，绝不静默回退计成绩；容错模式（fallback 混合策略）须逐次记录原因。

## 树训练与导出（已实现部分）

- 训练：`training/train_tree.py`（默认 GBR 64×3×0.05、squared_error、seed 固定、min_samples_leaf 20；首轮网格 ≤ {32,64,128}×{2,3}；按局划分验证；组内权重归一）。离线选型看组内 Top-1 一致率/联合分配一致率（初始工程目标 ≥90%，须报实际值与难例）。
- 导出：`export/exporter.py` → `models/<name>/model.json`（全精度阈值、missing_left、学习率单次计入、float32 输入转换显式记录）；部署运行时 `export/rule_model.py` 仅标准库。等价验收 ≤1e-6（已测试）。
- 数据协议与标签定义见 DATA_PROTOCOL.md；特征定义见 medivac/features.py 模块 docstring（FEATURE_SCHEMA 与代码同源，schema 不符拒绝加载）。
